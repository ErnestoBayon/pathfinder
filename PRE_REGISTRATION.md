# Pre-Registration: AI Priority Ordering A/B Experiment
**Date:** 2026-06-22  
**Author:** Ernesto Bayon  
**Project:** Pathfinder — AI-powered task manager for Data Scientists  
**Repo:** github.com/juanbayonugarte-source/pathfinder  
**Status:** Pre-registered (see commit hash on this file)

---

## 1. Background

Pathfinder is a single-user AI task manager where an LLM (claude-sonnet-4-6)
acts as a PM agent. The agent can create, update, and suggest tasks via tool
use. When creating a task, the agent assigns a priority level (high / medium /
low) based on conversational context. This experiment tests whether AI-assigned
priority ordering causally improves task completion rates compared to a
deterministic due-date baseline.

---

## 2. Research Question

Does displaying tasks ordered by AI-assigned priority (high → medium → low)
increase the 7-day task completion rate, compared to ordering by due date alone?

---

## 3. Hypothesis

**H₀:** AI priority ordering has no effect on 7-day task completion rate.  
**H₁:** AI priority ordering increases 7-day task completion rate.

Direction: one-sided (we expect a positive effect).  
Test: two-sample t-test, α = 0.05, power = 0.80.

---

## 4. Variants

| Variant | Description |
|---|---|
| **Control** | Tasks ordered by `deadline ASC` (nulls last), AI priority ignored in display |
| **Treatment** | Tasks ordered by AI priority (`high → medium → low`), then `deadline` within group |

---

## 5. Primary Metric

**7-day task completion rate**

```
completion_rate = COUNT(tasks WHERE completed_at <= created_at + 7 days)
                / COUNT(all tasks assigned to user)
```

Requires: `tasks.completed_at` (added 2026-06-22) and `tasks.created_at`.

---

## 6. Secondary Metrics

- **Time-to-completion:** median hours from `created_at` to `completed_at`
- **Overdue rate:** share of tasks where `completed_at > deadline` (non-null deadlines only)
- **Subtask completion rate:** completion rate of subtasks under treated/control parent tasks

---

## 7. Guardrail Metrics (must NOT degrade in treatment)

- Tasks created per user per week
- Daily active sessions (messages per day in `messages` table)
- Suggestion approval rate: `approved / (approved + rejected)` from `experiment_events`

---

## 8. Randomization

- **Unit of randomization:** `user_id` (user-level, not task-level)
- **Rationale:** Task-level randomization would violate SUTVA — the display
  order of one task affects the perceived priority of adjacent tasks.
- **Assignment method:** `hash(user_id || experiment_id) % 2`
  - 0 → control, 1 → treatment
  - Deterministic and reproducible from `user_id` alone.

---

## 9. Analysis Plan

Executed in order; each subsequent analysis is a robustness check.

1. **Descriptive:** completion rates by variant, histograms of time-to-completion
2. **Primary:** two-sample t-test on completion rates
3. **Causal (primary estimator):** DoWhy backdoor adjustment
   - Covariates: tasks_per_week, avg_priority_assigned, has_deadline_rate
4. **Causal (robustness 1):** Double ML via EconML
5. **Causal (robustness 2):** Propensity Score Matching
6. **Heterogeneous effects:** CATE via EconML (by task complexity, engagement)
7. **DiD (if panel data available):** pre/post completion rates by variant
8. **Refutation tests:** random_common_cause, placebo_treatment, data subset

---

## 10. Sample Size & Power

- Baseline completion rate assumed: 0.50
- Minimum detectable effect (MDE): 0.05 (5 percentage points)
- α = 0.05 (two-tailed), Power = 0.80
- Required N per arm: ~769 users (~1,538 total)
- **Simulation target: 3,000 users** to ensure margin

---

## 11. Data Generation Process (Simulation)

Since Pathfinder currently has N=5 real users, the primary analysis uses
synthetic data generated by a Python DGP (Data Generating Process) that
mirrors Pathfinder's DB schema and realistic behavioral assumptions.

Pilot data from real users (N=5) is used only to:
- Validate that instrumentation works end-to-end
- Provide directional estimates for DGP parameter calibration

Pilot data is **not** used for causal inference. This limitation is stated
explicitly in the paper.

---

## 12. Limitations (Pre-stated)

- Primary data is synthetic; real-world generalizability is unknown.
- Small pilot (N=5 real users) cannot be used for statistical inference.
- SUTVA holds by assumption in simulation; partially holds in pilot
  (no social features in Pathfinder today).
- LLM priority assignment is non-deterministic across API calls;
  treatment is defined by *display order*, not by re-running the LLM.

## 13. Event Schema (Instrumentation)

All behavioral events are logged to `experiment_events` table (added 2026-06-22):

| event_type | Trigger |
|---|---|
| `task_created` | POST /api/projects/[id]/tasks |
| `task_completed` | PATCH /api/tasks/[id] → estado = 'done' |
| `status_changed` | PATCH /api/tasks/[id] → estado changes |
| `priority_changed` | PATCH /api/tasks/[id] → prioridad changes |
| `suggestion_approved` | User clicks Approve in SuggestionsPanel |
| `suggestion_rejected` | User clicks Reject in SuggestionsPanel |
| `variant_assigned` | First time user_id seen in experiment context |
